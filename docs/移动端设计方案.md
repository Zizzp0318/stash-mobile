# Stash Mobile · iOS 移动端设计方案

> ⚠️ **本文的路线选型部分已被取代**（2026-10-25 决策变更）：
> 只做原生（跳过 PWA）、GitHub 仓库公开、范围从「只读浏览」扩到「手机上传素材」。
> 落地细节见 **`双向同步实施方案.md`**。本文保留的技术判断（云编译流水线、ATS、Cookie vs `?t=`、
> `UIScrollView` 缩放、HEIC 限制、7 天续签的三种解法）仍然有效。

> 目标：把 `Stash`（Windows 桌面素材库）的「手机访问」能力做成一个 **仅 iOS** 的原生移动应用。
> 约束：只有 Windows 电脑、只有免费 Apple ID（个人签名）、不上架 App Store。
> 现状：桌面端 `electron/services/remote.ts` 已经实现了一套完整的只读 HTTP 服务，移动端**不需要重写后端**。

---

## 0. 一句话结论

**原生 App 可以做，但必须走「云端 macOS 编译 + 本地 Sideloadly 签名」这条流水线**——Windows 无法编译任何 iOS 二进制（Swift / Flutter / React Native / Capacitor 全部一样，因为最终都要 `xcodebuild`）。

而免费 Apple ID 的 **7 天签名有效期**是这条路上唯一躲不掉的硬伤。因此建议**双轨并行**：

| 轨道 | 形态 | 用途 | 是否会过期 |
|---|---|---|---|
| A 轨（先做） | PWA（升级现有手机页） | 日常在手机上看库，**今天就能用** | 永不过期 |
| B 轨（正式形态） | SwiftUI 原生 App | 相册保存、离线缓存、Face ID、原生手势 | 每 7 天续签 |

A 轨不是「凑合方案」，它是这个项目**最理性的兜底**：手机端只需要「看」，而 PWA 加到主屏后没有地址栏、有独立图标、有启动图，观感和原生 App 差异很小，且不受 7 天限制。B 轨才是你要的「移动应用」，负责那些网页做不好的事（存相册、离线、系统集成）。

## 1. 约束换算：先把「不可能」排除

| 约束 | 直接后果 | 应对 |
|---|---|---|
| **只有 Windows** | 本地无法 `xcodebuild`，出不了 `.ipa` | GitHub Actions 的 `macos-14` runner 编译**未签名** ipa，约 3–5 分钟；Sideloadly 在 Windows 上只负责「签名 + 安装」，这件事它做得很好 |
| **免费 Apple ID** | 证书 7 天失效；同时最多 3 个 App；每 7 天最多 10 个 App ID；**不支持 Push / iCloud / App Groups / Network Extension / Associated Domains** | ①不设计任何推送功能（刷新靠前台拉取）②不做分享扩展（需要 App Groups）③不内置 VPN，异地用 Tailscale 官方 App |
| **不上架 App Store** | 无需审核，Info.plist 可完全放开 | `NSAllowsArbitraryLoads=true` 直接用明文 HTTP，不用折腾自签证书 |
| **iOS 16+** | 本地签名的 App 必须开启**开发者模式** | 设置 → 隐私与安全性 → 开发者模式 → 开启并重启（只需一次） |
| **手机与 PC 不一定同网** | 家庭外无法直连内网 IP | 两端各装一个 Tailscale（免费），走 `100.x` 地址；桌面服务已监听 `0.0.0.0`，天然支持 |

> ⚠️ 关键坑：`100.64.0.0/10`（Tailscale 网段）**不属于** iOS ATS 的 `NSAllowsLocalNetworking` 豁免范围。所以不要指望 `NSAllowsLocalNetworking`，直接 `NSAllowsArbitraryLoads=true`，一次到位。

## 2. 三条路线对比

| | **PWA（升级现有页）** | **SwiftUI 原生（推荐）** | **Capacitor 壳** |
|---|---|---|---|
| Windows 上能出包 | ✅ 完全不需要打包 | ⚠️ 需 GH Actions 云编译 | ⚠️ 同样需云编译 |
| 安装方式 | Safari → 添加到主屏 | Sideloadly | Sideloadly |
| 7 天续签 | ❌ 不需要 | ✅ 需要 | ✅ 需要 |
| 包体积 | 0 | ~2–3 MB | ~8–12 MB |
| 手势 / 转场 | 一般（浏览器限制） | 原生最佳 | 近似原生 |
| 视频播放 | HTML5 video | AVPlayer（画中画、后台音频） | HTML5 video |
| 保存到相册 | 分享菜单 / 长按（好于预期，但一步变两步） | 一键 `PHPhotoLibrary` | 需插件 |
| 离线浏览 | 需 HTTPS 才能用 Service Worker（**明文 HTTP 无法离线**） | 原生磁盘缓存，天然离线 | 原生层可缓存 |
| 复用现有代码 | 100%（页面已存在） | 0%（重写 UI，但接口全复用） | ~80% |
| 结论 | **先做，立刻可用** | **正式形态** | ❌ 不推荐 |

**为什么不选 Capacitor**：它和原生一样要云编译、一样 7 天续签，却多背一个 8MB 的 WebView 运行时，视频和手势还不如原生。既然都要付「云编译」这个成本，就直接拿原生体验。

**为什么不上 Flutter / RN**：同理——都要 macOS 出包，却带来双倍的调试成本和包体积，而这个 App 的 UI 复杂度很低（网格 + 查看器 + 设置三屏），SwiftUI 是最省的路。

## 3. 原生 App 架构

```
┌─────────────────────────────────────────────┐
│  UI (SwiftUI)                                │
│  素材网格 · 全屏查看器 · 目录 · 设置          │
├─────────────────────────────────────────────┤
│  Store (@Observable, 主线程)                 │
│  LibraryStore  ConnectionStore  ThumbCache    │
├─────────────────────────────────────────────┤
│  Net (async/await URLSession)                │
│  APIClient  ← token 自动注入 (?t=)            │
├─────────────────────────────────────────────┤
│  Cache                                       │
│  NSCache 内存 + Caches/thumbs 磁盘 LRU        │
├─────────────────────────────────────────────┤
│  Security                                    │
│  Keychain(token) + 可选 LocalAuthentication   │
└─────────────────────────────────────────────┘
                    ↓ HTTP (LAN / Tailscale 100.x)
        Stash Desktop · http://<ip>:5273
        electron/services/remote.ts（已存在）
```

**刻意不做的三件事**（v1 边界，与桌面端一致）：
1. **不做离线数据库**。v1 只缓存缩略图 + 内存索引；`GRDB/SwiftData` 离线全库索引留到 v2（等真有「地铁里看库」的需求再做）。
2. **不做写操作**。不上传、不打标、不删除。桌面端 `remote.ts` 的注释已经明确 v1 只读，移动端跟着这个边界走，安全模型最简单。
3. **不内置隧道**。免费签名没有 Network Extension 权限，异地访问交给 Tailscale App。

## 4. 页面与交互（iPhone）

**Tab 结构（3 个，别做 4 个）**

```
① 素材   ② 目录   ③ 设置
```

标签（Tag）不做成 Tab，做成素材页顶部的**横向 chips**——和现有网页版一致，也符合「筛选是网格的属性、不是独立页面」的直觉。

### ① 素材页
- 大标题 `Stash` + 右上角连接状态点（绿=已连 / 灰=未连）
- 搜索栏（`.searchable`，防抖 300ms，调 `/api/assets?q=`）
- 标签 chips 横向滚动，单选，再点取消
- **瀑布流网格**：2 列，卡片高度按 `width/height` 预先算好 → 无布局跳动（API 已返回宽高，这是能做好瀑布流的前提）
- 缩略图 `AsyncImage` 走磁盘 LRU，`loading="lazy"` 等价物 = 滚动到可视区才请求
- 触底自动加载下一页（`offset` 分页，现有接口已支持）

### ② 全屏查看器（拉开差距的地方）
网页版只能单张看，原生可以做到：
- **左右滑动切换上一张 / 下一张**（水平分页，预取相邻 2 张缩略图）
- 双指缩放 + 双击缩放居中 + 拖动平移 ——**用 `UIScrollView` 包 `UIImageView`（`UIViewRepresentable`），不要纯 SwiftUI 手势**。纯 SwiftUI 做「双击以触点为中心缩放」非常别扭，ScrollView 自带 `minimumZoomScale` 一下就对了。
- **下滑手势关闭**（interactive dismiss）+ 背景渐隐
- 底部工具栏：`保存到相册` / `信息` / `分享`
- 视频：`AVPlayer` + 自定义控制条，`allowsPictureInPicturePlayback`；服务端已支持 Range，拖动进度条流畅
- **大图必须 downsample**：手机内存有限，1 亿像素的图直接 `UIImage(data:)` 会 OOM。用 `CGImageSourceCreateThumbnailAtIndex` 按屏幕尺寸降采样。

### ③ 目录页
- 树形列表，按 `depth` 缩进，右侧显示子树素材数（接口已算好）
- 点进目录 → 回到素材页并带上 `folder` 过滤

### ④ 设置页
- 服务器地址（可手动改，含最近历史）
- 配对状态 / 重新配对（6 位码）
- 缩略图缓存占用 + 清空
- 关于 / 版本 / `Tailscale 使用提示`

### 首次连接流程
```
输入 http://192.168.x.x:5273  →  GET /api/ping 探测  →  输入 6 位配对码
      →  POST /api/pair 拿到 token  →  存 Keychain  →  进主界面
```
- 地址栏默认填**上次成功的地址**，并给出「本机局域网 IP / Tailscale IP」两个候选（桌面端 `/api/ping` 可顺便回传自己见过的 IP，或直接让用户在设置面板照抄）
- **v1.1 加分项：二维码配对**。桌面端设置面板渲染一个二维码，内容 `stash://pair?host=192.168.1.200&port=5273&code=371283`，手机用 `AVFoundation` 扫一下即完成，省掉在手机上敲 IP 的折磨。

## 5. 接口契约

### 已有接口（直接复用，共 7 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/pair` | 6 位码换 token（Cookie） |
| GET | `/api/assets?q=&folder=&tag=&limit=&offset=` | 分页素材列表 |
| GET | `/api/folders` | 目录树 + 子树计数 |
| GET | `/api/tags` | 标签 + 计数 |
| GET | `/api/thumb/:hash/grid.webp` | 网格缩略图 |
| GET | `/api/thumb/:hash/detail.webp` | 详情缩略图 |
| GET | `/api/media/:id` | 原图 / 视频（支持 Range，`?dl=1` 附件下载） |
| GET | `/api/events` | SSE 变更通知（原生端仅前台使用） |

### 认证方式的调整（重要）

现有网页版靠 `Set-Cookie` 建立会话。**原生端不要用 Cookie**，理由：
- `AVPlayer` 和 `URLSession` 的 Cookie 存储不互通，视频请求会 401；
- 拼接媒体 URL 时无法加自定义头。

**统一改成 `?t=<token>`**：服务端 `authed()` 已经同时接受 query 和 cookie（`remote.ts:140`），所以 App 里所有 URL 统一拼 `?t=`，图片、视频、下载全部一次搞定。API 请求额外带 `Authorization: Bearer <token>` 更规范，但非必需。

### 建议新增（全部增量，不破坏现有网页版）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/ping` | **免鉴权**。返回 `{app:'stash', v:1, name:'素材库'}`，用于连接探测（现在只能用 `/` 返回 HTML 猜，很别扭） |
| POST | `/api/pair` | 响应体补 `{ok:true, token:'...'}`。现在 token 只藏在 Cookie 里，原生端读 `Set-Cookie` 很脏 |
| GET | `/api/assets` | 补返回 `rating`、`is_fav`、`duration_ms`、`palette`；补 `sort=` 参数（`-imported_at` / `name` / `-size`） |
| GET | `/api/asset/:id` | 单项详情（note / exif / gen_meta / tags），给查看器的「信息」面板用 |

以上 4 处加起来约 60 行改动，都在 `remote.ts` 内部，不影响桌面端。

## 6. 构建与签名流水线（Windows-only 也能跑通）

### 为什么用 XcodeGen
Windows 上编辑 `.xcodeproj`（二进制 plist）是灾难，改动必冲突。方案：**仓库里只存 `project.yml`**，CI 里用 `xcodegen` 生成工程。源码在 Windows 上写，工程文件不入库。

```
Stash app/
├── project.yml                 # 工程定义（手写，可读，可 diff）
├── Sources/
│   ├── App/StashMobileApp.swift
│   ├── Net/APIClient.swift
│   ├── Store/LibraryStore.swift
│   ├── Store/ConnectionStore.swift
│   ├── Cache/ThumbCache.swift
│   ├── Models/Asset.swift
│   ├── UI/GalleryView.swift
│   ├── UI/ViewerView.swift
│   ├── UI/ZoomableImage.swift      # UIScrollView 包装
│   ├── UI/FolderView.swift
│   └── UI/SettingsView.swift
├── Resources/Info.plist
├── Resources/Assets.xcassets
└── .github/workflows/ios.yml
```

### 关键 Info.plist
```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key><true/>
</dict>
<key>NSLocalNetworkUsageDescription</key>
<string>用于连接你电脑上的 Stash 素材库</string>
<key>NSPhotoLibraryAddUsageDescription</key>
<string>把素材保存到你的相册</string>
<key>NSCameraUsageDescription</key>       <!-- 仅二维码配对时需要 -->
<string>用于扫描电脑端显示的配对二维码</string>
<key>NSFaceIDUsageDescription</key>        <!-- 可选 -->
<string>用于解锁素材库</string>
<key>UISupportedInterfaceOrientations</key>
<array><string>UIInterfaceOrientationPortrait</string></array>
```

### 流水线（`.github/workflows/ios.yml`）
```yaml
name: ios-unsigned-ipa
on: [push, workflow_dispatch]
jobs:
  build:
    runs-on: macos-14            # 免费额度：公开仓库不扣分钟；私有仓库 2000 分钟/月（macOS 按 10 倍计）
    steps:
      - uses: actions/checkout@v4
      - run: brew install xcodegen
      - run: xcodegen generate
      - name: Build unsigned
        run: |
          xcodebuild -project StashMobile.xcodeproj \
            -scheme StashMobile -sdk iphoneos -configuration Release \
            -derivedDataPath build \
            CODE_SIGN_IDENTITY="" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO
      - name: Package IPA
        run: |
          mkdir -p Payload
          cp -R build/Build/Products/Release-iphoneos/StashMobile.app Payload/
          zip -qr StashMobile.ipa Payload
      - uses: actions/upload-artifact@v4
        with: { name: StashMobile-ipa, path: StashMobile.ipa }
```

### 本地（Windows）安装步骤
```
1. GitHub Actions 跑完后，浏览器下载 StashMobile.ipa 产物
2. iPhone 用数据线连电脑，解锁并「信任此电脑」
3. 打开 Sideloadly → 拖入 ipa → Apple ID 填你的免费账号 → Start
4. iPhone：设置 → 通用 → VPN与设备管理 → 信任该开发者
5. iPhone：设置 → 隐私与安全性 → 开发者模式 → 开启 → 重启（iOS 16+ 必须）
6. 打开 App → 输入地址 + 配对码
```
> 重签同一个 Bundle ID **不会丢失 App 内数据**（Keychain 里的 token 也还在），所以每周续签后不用重新配对。

## 7. 7 天续签的三种解法

| 方案 | 操作成本 | 说明 |
|---|---|---|
| **① 手动 Sideloadly 重签** | 每周约 3 分钟 | 最稳。插线或开 Sideloadly 的 Wi-Fi 安装，重签同 Bundle ID |
| **② SideStore / AltStore 自动续签** | 一次性折腾，之后零成本 | 用配对文件 + 本地 VPN 在设备上自动重签。能彻底解决痛点，但要先用 `jitterbugpair` 在 Windows 上导出配对文件，步骤偏硬核 |
| **③ 关键功能留在 PWA** | 0 | 即使 App 过期打不开，主屏上的 PWA 依然随时可用——这是双轨方案最实际的价值 |

**建议**：先用 ①，确认这个 App 你真的每天在用，再折腾 ②。不要为了一个还在迭代的 App 先花两小时配 SideStore。

## 9. 已知的坑（都是踩过或能预见的）

1. **`imported_at` 是整数时间戳（epoch 毫秒），不是字符串**。网页版曾照抄桌面端的字符串写法，导致 `TypeError`、点击卡片根本打不开。原生端解码务必用 `Int64` 再 `Date(timeIntervalSince1970:)`。
2. **`content_hash` 要先过 `isThumbHash` 闸门**才能拼缩略图路径。接口已经返回 `hash`（不合法时为 `null`），App 里 `hash == nil` 就显示类型占位图标，别硬拼 URL。
3. **ATS 拦明文 HTTP**。`NSAllowsArbitraryLoads` 必须开，且 `100.x` 不在 local networking 豁免内。
4. **后台 SSE 会断**。`AVPlayer`/`URLSession` 在 App 进入后台后连接被挂起，别指望像网页一样常驻 SSE。原生端策略：`scenePhase == .active` 时拉一次 `/api/assets`（首屏很快），SSE 仅作前台增量提示。
5. **大图内存**。必须 downsample，尤其 AI 生成图动辄 4K–8K。
6. **HEIC / WebP / GIF**。`UIImage` 对 WebP 支持要 iOS 14+，HEIC 原生支持；GIF 需要用 `CGImageSource` 逐帧或直接交给 `FLAnimatedImage` 之类。服务端已经是 `.webp` 缩略图，注意别用只认 PNG/JPEG 的老写法。
7. **中文文件名下载**。服务端已经做了 RFC 5987 编码（`filename*=UTF-8''`），原生端保存到相册时不要自己再拼文件名，走 `PHAssetChangeRequest.creationRequestForAsset(from:)` 更省事。
8. **App ID 配额**。免费账号每 7 天最多 10 个 App ID，别反复改 Bundle ID 调试，固定一个。
9. **服务端「关闭手机访问」= 立即断开**。App 要给出明确文案（「电脑端已关闭手机访问」），而不是转圈。

## 10. 需要你确认的 3 件事

1. **PWA 先行，还是直接原生？** 我的建议是 M0（PWA，当天可用）→ M1 原生。如果你只想做原生，M0 也可以跳过，但那就失去了「App 过期时还有东西能用」的兜底。
2. **GitHub 仓库**：云编译需要把代码推到 GitHub（公开仓库不消耗 Actions 分钟；私有仓库 macOS 按 10 倍计，2000 分钟/月 → 约 40 次构建/月，够用）。你倾向公开还是私有？
3. **移动端要不要「写」？** 现有服务是严格只读。如果以后想在手机上收藏/打标/上传，需要新增 POST 接口 + 重新设计鉴权（`?t=` 在 URL 里不适合承载写权限）。v1 建议保持只读。
